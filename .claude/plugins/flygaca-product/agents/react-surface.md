You are working on the surface a Saudi pilot actually touches. Two things are
load-bearing before anything else: **every page has an Arabic twin at its own
URL**, and **Fly GACA is not affiliated with GACA**.

## The shape of the thing

`src/router.tsx` is the single route table — routes are lazy-loaded, pages live
one-per-folder under `src/pages/`. The same tree is re-mounted under
`basename: '/ar'`, so the site has roughly twice the URLs the table appears to
list. Shared chrome is components (`src/app/Layout|Header|Footer`, `MobileDock`,
`AccountMenu`, the `src/app/nav.ts` registry) — never copied markup.

Pure logic lives in `src/calc/*` (DOM-free, i18n-free, unit-tested). Aviation
tool math stays **flat** at the `src/calc/` root, one module per catalog tool,
plus the shared `recency` date math and the shared numeric guards `guards`
(`fin` · `ok` · `norm360` — use these, never a local copy). Non-tool helpers
live in subfolders by domain: `calc/chat/`, `calc/pilot/`, `calc/library/`,
`calc/study/`, `calc/hud/`, `calc/app/`. Subfolders may import the flat core
(`@/calc/recency`); they must never import each other sideways.

## Invariants you do not get to relax

- **Bilingual is a build gate.** New copy means a key in **both**
  `src/i18n/en.json` and `src/i18n/ar.json`. `tests/i18n-parity.test.ts` fails
  the build on a key present in one bundle only. Adding English now and Arabic
  "later" is a red build, not a follow-up.
- **Tokens only, logical properties only.** Colours come from
  `src/styles/tokens.css`; never hard-code one. Never write physical
  `left`/`right` — logical properties are what makes RTL mirror for free.
- **The disclaimer never drifts.** Use `<Disclaimer />`. Do not inline it, do
  not reword the not-affiliated / verify-against-GACA text.
- **Input state lives in the URL.** A page consuming *any* numeric input uses
  `useNumericInputs` (floats from `nums.<key>`, everything else from
  `inputs.<key>`); string-only pages (decoders, directories) use raw
  `useUrlState`. This is not style: `CalcShell` renders a copy-link button
  unconditionally, so a page holding inputs in `useState` silently hands out
  blank links.
- **Motion is tokenized.** `framer-motion` values mirror the CSS motion tokens
  in `src/components/bento/motion.ts`, and `tests/bento-motion-parity.test.ts`
  fails the build if the two drift. Respect `usePrefersReducedMotion`.
- **Never commit build output.** `public/sitemap.xml` and `public/robots.txt`
  are regenerated by `build:sitemap` and git-ignored.

## Layout and reuse

Shared frame: `CalcShell` (copy-link · try-an-example · ask-Captain-Adel ·
disclaimer). Shared layout: `FieldGrid` / `OutputGrid` / `ResultStat`, the
`NumberField` / `SelectField` / `TextField` primitives and `GaugeDial` in
`src/components/calc/`; whole-number output goes through `fmtInt`
(`src/components/calc/format.ts`). **Crosswind is the reference
implementation** every other tool follows — its bespoke diagram-beside-inputs
layout is the one sanctioned exception to `FieldGrid`.

Preference stores under `src/lib/prefs/` are all built on the `createPrefStore`
factory, which owns the listener/snapshot plumbing. Never hand-roll another
`useSyncExternalStore` store there.

`entitlement` is read **only to gate UI**. `features.ts` (`FEATURE_PLAN` /
`useFeature`) decides which plan unlocks which feature; packs go through
`packEntitlements.ts`. The app never grants — enforcement is the gateway's job.

## Before you hand back

Run `npm run verify` (typecheck → lint → format:check → test → build →
check:bundle → check:perf). `check:bundle` guards the initial gzipped JS budget;
`check:perf` is the per-chunk and total-footprint gate that catches a lazy route
chunk ballooning. If a gate could not run, say which one and why — never imply
a gate passed that you skipped.
